Signing in on macOS fails for every account with every correct password. The
cause is not the credentials and not the keychain: Firebase rejects the request
with 403 PERMISSION_DENIED, reason API_KEY_IOS_APP_BLOCKED, because the macOS
bundle id com.uractor.uractormacos is not on the iOS-app allowlist of the API
key it shares with the iOS registration.

The server-side half of that is a console change and cannot be made from here.
What can be made from here is the part that wasted the time: the app maps this
to AuthFailure.unknown and shows "Something went wrong. Please try again.",
which is false twice over. Nothing went wrong that the person can see, and
trying again cannot ever work. They are sent round a loop with no exit.

Scope of this task:

- Classify a blocked-caller failure as its own AuthFailure, detected from the
  machine-readable reason token in the error, since the code is only the
  generic internal-error.
- Give it a message in both .arb files that says retrying will not help.
- Cover it in test/auth_error_test.dart, including that it does not swallow an
  ordinary internal-error.
- Correct README.md and docs/releases.md, which currently tell the reader that
  a macOS sign-in failure means the keychain entitlement. That was true once
  and is now the wrong first place to look.
- Patch bump, since this is a fix.

Deliberately not done: firebase_options.dart still points macOS at the iOS
registration with a stale placeholder iosBundleId. Correcting that means
registering a macOS app in the console and regenerating the file, so editing it
by hand now would replace one untruth with another.
